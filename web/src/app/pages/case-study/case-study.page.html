Case study

DocRoof: document governance for construction projects

An independent portfolio project exploring how a construction company's document control could be built with Angular, ASP.NET Core and SQL Server — with the business rules enforced where they belong: on the server and in the database.

Project status: Phase 2 of 3 complete. The document vertical slice (Phase 1) and the RFI/submittal workflows, comments, audit trail, review queue, reminders, notifications and live insights (Phase 2) are built and tested. Extraction, security hardening and deployment readiness (Phase 3) are in progress. Measured test results are recorded in docs/STATUS.md in the repository.

The problem

On a building project, hundreds of drawings and specifications change over months. Site teams need the current revision; reviewers need to know which revision a question refers to; managers need to prove who approved what. When this lives in email threads and shared folders, superseded documents get built from and approvals are hard to trace.

Users and roles

Roles
Role (per project) Responsibilities
Document Controller Uploads, organizes, versions and distributes records.
Project Manager Creates projects, approves RFI answers, resolves escalations.
Reviewer Decides assigned submittals and answers assigned RFIs.
Requester Creates RFIs and sees responses.

Business rules enforced today

  • Document numbers are unique per project; revision labels are unique per document.
  • A revision's content columns can never change after insert (service check, EF Core interceptor, SQL trigger).
  • Uploads are accepted only when their first bytes match an allowed type (PDF, TXT, PNG, JPG) and size limit.
  • Files are stored under generated keys; user file names are only shown, sanitized, never used as paths.
  • Accessing another tenant's or project's records returns 404, so existence is not leaked.
  • Audit events are append-only and written in the same transaction as the change.
  • RFIs follow Draft → Submitted → Assigned → Answered → Closed (Reopened → Assigned); only the assignee answers, only a project manager approves and closes, and a second approval returns 409.
  • RFIs cite a revision of the same project and a page within its page count; citations stay pinned.
  • Submittals allow one decision per review cycle by the assigned reviewer; Revise & Resubmit needs a newer revision and starts a new cycle.
  • Stale rowversions return 409, so concurrent edits never overwrite each other silently.

Architecture

A modular monolith: the Angular app calls the ASP.NET Core REST API over HTTPS, the API's services enforce validation, authorization and transactions, and EF Core talks to SQL Server. In production the API also serves the built Angular files, so the auth cookie stays first-party.

Why this stack fits an enterprise construction team

Construction companies commonly run Microsoft-centred estates: SQL Server for project and financial data, .NET services behind the firewall, and browser front-ends for field and office staff. DocRoof uses that same stack and patterns a team would expect to maintain: typed REST contracts, migrations under version control, constraints in the database, and automated tests that run against a real SQL Server.

Known limitations (current)

  • No malware scanning of uploads; type sniffing and size limits only.
  • No OCR: image-only PDFs are shown with a "no text layer" notice.
  • No hosted deployment yet; the owner must provide accounts (see docs/OWNER_TODO.md).
